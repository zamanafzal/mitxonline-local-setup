# Part 2 — Tutor LMS + MITx Online Integration

This document connects **Open edX (Tutor LMS)** to **MITx Online** for OAuth2-based identity and optional full LMS↔MITxOnline SSO.

**Prerequisite:** [Part 1](part1-mitxonline-mitlearn-sso.md) must be completed and working first.

After following this guide:
- Open edX LMS can use MITx Online as an OAuth2 identity provider (optional)
- Staff can access LMS Django admin via password login
- Learners can use the authn MFE with or without MITx Online SSO

> **Automation:** Instead of following these steps manually, you can run `scripts/setup_mitxonline_lms.sh` from the MITx Online repo root. See the [README](../README.md) for details.

## Step 2 — Add CORS and LMS settings to MITx Online `.env`

Add or update these values in the MITx Online `.env`:

```dotenv
# Docker base URL for container-to-container calls from LMS
MITXONLINE_DOCKER_BASE_URL=http://mitxonline-varnish-1

# CORS — allow the LMS and all MFE origins
CORS_ALLOWED_ORIGINS=http://open.odl.local:8062,http://localhost:8062,http://local.openedx.io:8000,http://apps.local.openedx.io:1984,http://apps.local.openedx.io:1993,http://apps.local.openedx.io:1994,http://apps.local.openedx.io:1995,http://apps.local.openedx.io:1996,http://apps.local.openedx.io:1997,http://apps.local.openedx.io:1999,http://apps.local.openedx.io:2001,http://apps.local.openedx.io:2002,http://apps.local.openedx.io:2025
CORS_ALLOWED_ORIGIN_REGEXES=http://apps\.local\.openedx\.io:\d+,http://local\.openedx\.io:\d+
CSRF_TRUSTED_ORIGINS=http://open.odl.local:8062,http://api.open.odl.local:8065,http://localhost:8062,http://local.openedx.io:8000,http://apps.local.openedx.io:1999,http://mitxonline.odl.local:9080

# Set true only if you use authn MFE with MitxOnline OAuth (full SSO). Default false.
OPENEDX_AUTHN_MFE_OAUTH2_CORS=false
```

### `OPENEDX_AUTHN_MFE_OAUTH2_CORS` (optional)

When set to **`true`**:

1. **Django** — Inserts `OAuth2AuthorizeRedirectCorsMiddleware`: answers OPTIONS preflight for `/oauth2/authorize/` and adds CORS headers to redirect responses for credentialed XHRs from Open edX MFE origins.
2. **Nginx** — `config/nginx.conf.erb` adds a `map` on `Origin` and a `location ^~ /oauth2/authorize` block that responds to OPTIONS with 204 and CORS headers before the request hits uWSGI.

After changing this flag:

```bash
docker compose up -d nginx web
```

Verify preflight (expect 204 and `access-control-allow-origin`):

```bash
curl -sI -X OPTIONS \
  -H "Origin: http://apps.local.openedx.io:1999" \
  -H "Access-Control-Request-Method: GET" \
  -H "Access-Control-Request-Headers: use-jwt-cookie" \
  "http://mitxonline.odl.local:8013/oauth2/authorize/?client_id=test" | grep -i access-control
```

Keep **`false`** if you do not rely on the authn MFE hitting MITx Online OAuth over XHR.

## Step 5 — Create the OAuth2 Application in MITx Online

Before the LMS can authenticate against MITx Online, you need an **OAuth2 Application** registered in MITx Online. This gives you a **Client ID** and **Client Secret** that the LMS will use.

### Option A — Use `configure_instance` (recommended)

MITx Online has a built-in management command that creates the OAuth2 app automatically:

```bash
docker exec mitxonline-web-1 python manage.py configure_instance macos --tutor-dev -S -D
```

> Use `linux` instead of `macos` if you are on Linux (requires `--gateway <docker-gateway-ip>`).

The command prints the credentials at the end:

```
== edX OAuth2 Application Details ==
Client ID: <your-client-id>
Secret: <your-client-secret>
```

**Save these values** — you will need them in Step 6.

### Option B — Create manually via Django admin

1. Go to `http://mitxonline.odl.local:8013/admin/oauth2_provider/application/`
2. Log in with your MITx Online superuser
3. Click **Add Application** and fill in:

| Field | Value |
|---|---|
| Name | `edx-oauth-app` |
| Client type | Confidential |
| Authorization grant type | Authorization code |
| Skip authorization | ✅ checked |
| Redirect uris | `http://local.openedx.io:8000/auth/complete/ol-oauth2/` |

4. After saving, copy the **Client ID** and **Client Secret** shown on the application detail page.

### Option C — Retrieve existing credentials

If the OAuth2 app was already created (e.g. by a previous `configure_instance` run):

```bash
docker exec mitxonline-web-1 python manage.py shell -c "
from oauth2_provider.models import Application
app = Application.objects.filter(name='edx-oauth-app').first()
if app:
    print(f'Client ID: {app.client_id}')
    print(f'Secret: {app.client_secret}')
else:
    print('No edx-oauth-app found. Run configure_instance or create one manually.')
"
```

## Step 6 — Update the LMS OAuth2 Provider config

The LMS needs to know where to find MITx Online's OAuth2 endpoints. Use the **Client ID** and **Client Secret** from Step 5.

1. Go to `http://local.openedx.io:8000/admin/third_party_auth/oauth2providerconfig/add/`
2. Log in with your LMS superuser
3. Fill in:

| Field | Value |
|---|---|
| Name | `MitxOnline` |
| Enabled | ✅ checked (or unchecked if you don't want LMS↔MITxOnline SSO) |
| Backend name | `ol-oauth2` |
| Key | *(Client ID from Step 5)* |
| Secret | *(Client Secret from Step 5)* |
| Other settings (JSON) | See below |

**Other settings JSON:**
```json
{
  "AUTHORIZATION_URL": "http://mitxonline.odl.local:8013/oauth2/authorize/",
  "ACCESS_TOKEN_URL": "http://mitxonline-varnish-1/oauth2/token/",
  "DISCOVERY_URL": "http://mitxonline-varnish-1/.well-known/openid-configuration",
  "API_ROOT": "http://mitxonline-varnish-1/",
  "logout_url": "http://mitxonline-varnish-1/logout/"
}
```

**Why two different URLs?**
- `AUTHORIZATION_URL` uses `mitxonline.odl.local:8013` — the **browser** navigates there
- All other URLs use `mitxonline-varnish-1` — the **LMS server** calls them container-to-container

**Disable via LMS shell (no Django admin needed):**

```bash
docker exec tutor_main_dev-lms-1 ./manage.py lms shell -c "
from django.apps import apps
from config_models.models import cache as config_models_cache
OAuth2ProviderConfig = apps.get_model('third_party_auth', 'OAuth2ProviderConfig')
OAuth2ProviderConfig.objects.filter(backend_name='ol-oauth2').update(enabled=False)
config_models_cache.clear()
print('Done — run: tutor dev restart lms')
"
```

## Step 7 — Open edX LMS: Django admin, authn MFE, and optional full SSO

Three independent goals:

| Goal | Where | SSO? |
|------|--------|------|
| **Staff / superuser** | **`/login?next=/admin&skip_authn_mfe=1`** | No |
| **Learners via authn MFE** | `http://local.openedx.io:8000/login/` → authn MFE | **No LMS↔MITxOnline OAuth** if provider disabled |
| **Learners + MITx Online OAuth** | Same MFE, MitxOnline TPA enabled | Yes — needs `OPENEDX_AUTHN_MFE_OAUTH2_CORS=true` |

### A — LMS Django admin (staff)

**`/admin/login/`** redirects to `/login?next=/admin` which may send you to the authn MFE.

For a **password-only** path: use **`http://local.openedx.io:8000/login?next=/admin&skip_authn_mfe=1`**.

### B — Authn MFE for learners **without** LMS↔MITx Online SSO (recommended)

1. Leave `FEATURES["ENABLE_AUTHN_MICROFRONTEND"]` as default (True)
2. **Uncheck "Enabled"** on MitxOnline `OAuth2ProviderConfig` (or don't create it)
3. If your stack has `THIRD_PARTY_AUTH_ONLY = True`, set to `False` or remove
4. Ensure `ENABLE_REQUIRE_THIRD_PARTY_AUTH` is not `True`
5. In Django admin → Waffle → Switches, ensure `user_authn.enable_login_using_thirdparty_auth_only` is **OFF**
6. Keep the LMS CORS block below

MITx Online keeps `OPENEDX_AUTHN_MFE_OAUTH2_CORS=false`.

### C — Optional: HTML login instead of authn MFE

```python
FEATURES["ENABLE_AUTHN_MICROFRONTEND"] = False
```

Or one-off: `http://local.openedx.io:8000/login/?skip_authn_mfe=1`.

### LMS CORS snippet

Add at the bottom of `$TUTOR_ROOT/env/apps/openedx/settings/lms/development.py`:

```python
# --- CORS for local MFEs + MITx Online hosts ---
from corsheaders.defaults import default_headers

CORS_ORIGIN_WHITELIST = [
    "http://apps.local.openedx.io:1984",
    "http://apps.local.openedx.io:1993",
    "http://apps.local.openedx.io:1994",
    "http://apps.local.openedx.io:1995",
    "http://apps.local.openedx.io:1996",
    "http://apps.local.openedx.io:1997",
    "http://apps.local.openedx.io:1999",
    "http://apps.local.openedx.io:2001",
    "http://apps.local.openedx.io:2002",
    "http://apps.local.openedx.io:2025",
    "http://local.openedx.io:8000",
    "http://mitxonline.odl.local:8013",
    "http://mitxonline.odl.local:9080",
]
CORS_ORIGIN_ALLOW_ALL = False
CORS_ALLOW_CREDENTIALS = True
CORS_ALLOW_HEADERS = list(default_headers) + ["use-jwt-cookie"]
LOGIN_REDIRECT_URL = "/"
ENABLE_REQUIRE_THIRD_PARTY_AUTH = False
```

Then: `tutor dev restart lms`.

### Optional: authn MFE **with** MitxOnline OAuth (full SSO loop)

Re-enable MitxOnline in `OAuth2ProviderConfig`, set `OPENEDX_AUTHN_MFE_OAUTH2_CORS=true` in MITx Online `.env`, then `docker compose up -d nginx web`.

### Tutor plugin (survives `tutor config save`)

Patch `openedx-lms-development-settings` with the same CORS block. Re-apply Step 3 network changes after `tutor config save`.

### Verify LMS CORS headers

```bash
curl -v -X OPTIONS \
  -H "Origin: http://apps.local.openedx.io:1999" \
  -H "Access-Control-Request-Method: GET" \
  http://local.openedx.io:8000/csrf/api/v1/token 2>&1 | grep -i access-control
```

## Troubleshooting

### LMS can't reach mitxonline for token exchange
- Verify: `docker network inspect mitxonline_default | grep tutor`
- If not connected: `docker network connect mitxonline_default tutor_main_dev-lms-1`
- Check Step 3 network changes

### LMS error: `502` fetching `http://mitxonline-varnish-1/.well-known/openid-configuration`
Check `docker compose ps` in MITx Online. Fallback: point URLs at `http://mitxonline-nginx-1:8013` instead.

### CORS / preflight on `mitxonline.odl.local:8013/oauth2/authorize/`
**Recommended:** disable MitxOnline `OAuth2ProviderConfig`, keep `OPENEDX_AUTHN_MFE_OAUTH2_CORS=false`. If re-enabling, set to `true` and verify OPTIONS.

### LMS still redirects `/login/` to authn MFE
Normal when authn MFE is enabled. Use `?skip_authn_mfe=1` or disable MitxOnline provider.

### "No oauth2 provider has been configured" (admin)
Work through: set `ENABLE_REQUIRE_THIRD_PARTY_AUTH = False`, set `THIRD_PARTY_AUTH_ONLY = False`, turn OFF waffle switch `user_authn.enable_login_using_thirdparty_auth_only`, remove `openedx-companion-auth` if not needed.

### LMS exception: `Can't fetch setting of a disabled backend/provider`
Use `/login?next=/admin&skip_authn_mfe=1` for staff. Don't navigate to `/auth/login/ol-oauth2/` when provider is disabled.

### `login_refresh` 401 and `favicon.ico` connection refused
Normal — harmless.

### After `tutor config save`, LMS loses network config
Re-apply Step 3 and run `docker network connect mitxonline_default tutor_main_dev-lms-1`.
